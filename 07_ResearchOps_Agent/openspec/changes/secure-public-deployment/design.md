# Design

## Context

动机见 [proposal.md](proposal.md)。本方案适用单台 Mac mini、单个 API 进程和少数可信受邀人员。

已检查的实现与主机状态：

- FastAPI 路由直接调用共享服务，没有统一认证或资源归属检查；环境授权接口可直接签发短期令牌，该令牌不是登录凭证。
- `AssessmentJobService.start()` 每次创建 daemon 线程；缓存条数上限不限制运行任务。同步评估和反馈重评也能调用真实模型，不能只保护后台入口。
- `AssessmentReviewSession` 没有 owner；评估文件有 TTL 和数量上限，但读取会刷新 TTL，进度只保存在内存。
- DeepSeek 适配器包含同步、异步、重试和协议回退路径，已提供输入材料上限、输出 token 上限和 usage 信息。
- 项目页抓取会检查 DNS 是否为公网地址，但 HTTP 客户端随后独立解析，存在校验与连接不一致的空间。其他采集器已有固定提供商或域名白名单，应保留这些约束。
- MVP 通过同源 `fetch` 请求 API；HTML 包含内联脚本和样式，直接启用严格 CSP 会影响页面，需要一并适配。
- 排查时本地 `/mvp/` 为 200，公网为 530/1033；系统 cloudflared 参数只有可执行文件，不能由进程存在推断隧道已连接。root 私有目录尚未读取成功，配置缺失的具体位置仍待部署时核实。
- Python 的用户 LaunchAgent 监听 `0.0.0.0:8000`；系统睡眠为 1 分钟，FileVault 已开启。

## Goals / Non-Goals

**Goals:**

- 身份、资源归属、执行准入和出站访问构成独立且都在服务端生效的边界，网页绕过不改变结果。
- 复用现有业务图和领域响应，使用小型持久化控制状态支持重启后撤销、归属及额度一致性。
- 将公网启用放在防护验证之后；安装与回滚均可审查，系统权限或外部条件不足时明确记录待完成项。

**Non-Goals:**

- 不建设账号注册、公开管理员页面、计费系统、OAuth、Redis 集群或多进程调度。
- 邀请码代表持有者资格，不证明真实身份；同一码共享会话额度和数据。默认每人独立发码，禁止把邀请码当公共口令。
- 不把模型预算等同于人民币账单精确硬封顶，也不承诺匿名攻击完全不可发生。

## Decisions

### 1. 邀请码作为稳定主体，服务端保存不透明会话

本地管理 CLI 生成 32 字节随机邀请码，仅生成时输出明文；存储 SHA-256 摘要、稳定 `principal_id`、标签、到期时间、停用时间和日额度。随机码无需采用低熵密码的慢哈希；拒绝自定义弱口令。会话同样使用 32 字节随机令牌，数据库仅存摘要和主体、创建时间、绝对到期时间。

公网 Cookie 名采用 `__Host-researchops_session`，设置 Secure、HttpOnly、SameSite=Strict、Path=/，不设置 Domain。每次兑换生成新令牌；服务端每次请求重新检查邀请码状态及会话到期，不使用无法立即撤销的长效自包含 JWT。CSRF 秘密绑定会话，仅由同源会话查询返回给页面内存，不进入 localStorage、URL 或日志。

建议接口：`POST /api/v1/access/sessions` 兑换，`GET /api/v1/access/session` 读取当前会话和 CSRF，`DELETE /api/v1/access/session` 退出。兑换请求只允许配置 Origin 与 JSON；查询需要登录且 no-store；退出和所有已登录写操作需要 Origin、CSRF 双检查。未登录查询返回 401；MVP 捕获 401 后清空旧结果并展示邀请码入口，不重复自动提交高成本操作。

替代：Cloudflare Access 能避免自建会话，但用户已选择邀请码体验；共享单个口令无法独立撤销或隔离数据；JWT 增加撤销复杂度，当前不采用。

### 2. 默认保护路由，匿名访问采用短白名单

公网为默认部署模式；新增显式 `local` 开发模式，校验其监听与部署参数只允许回环。本地模式使用隔离的开发主体和控制状态，不能作为生产数据库归属兜底。公网模式下安全配置、数据库权限或迁移状态错误直接启动失败；运行期间控制状态故障返回通用 503。

统一接入层在业务处理前完成 Host、请求体上限、身份、Origin/CSRF 和限流校验。匿名白名单仅为登录 shell 及必要静态文件、兑换接口和 `/health` 最小存活状态；业务路由未来新增也自动受保护。公网 `/docs`、`/redoc`、`/openapi.json` 关闭；另设受保护 readiness，仅输出安全状态，不发起付费调用。没有浏览器重定向的 API 返回 JSON 401，避免前端把登录 HTML 解析为结果。

### 3. SQLite 保存控制状态，评估内容沿用现有文件存储

在 `.runtime/security/` 内建立 SQLite 状态库，目录 0700、库及辅助文件 0600；设置有限忙等待、事务和版本化迁移。新增表覆盖 invitations、sessions、resource_owners、operations、daily_usage 及最小审计。生产保持一个 uvicorn worker，获取实例锁；多 worker 启动拒绝，防止内存执行槽被重复计算。SQLite 不是多主调度方案。

`resource_owners` 按资源类型和 UUID 绑定主体，记录创建时间和绝对到期；请求方 owner 字段不能成为权限来源。API 调用服务前先按主体查归属，业务服务和后台执行也接收可信主体上下文；不能仅给 HTTP 入口加一个容易遗漏的 ID 检查。后台上下文显式传入，禁止依赖未传递到线程的隐式上下文。

工作流生成评估后，先持久化可信归属，再公开响应/任务完成状态。文件与 SQLite 不具备共同事务：任一写失败不公开资源，孤儿文件或映射默认不可访问并由清理处理，绝不能因映射缺失允许读取。读取授权要在调用会刷新 TTL 的旧 store 之前完成。保留文件存储内部结构，增加创建时间/绝对到期封装，默认绝对保留 24 小时、100 份结果；清理同步回收归属映射。

旧文件不自动分配给首个用户；本地 CLI 提供按明确 assessment ID 绑定主体的迁移操作。备份后操作，审计只记录 ID。重启后恢复评估归属；未结束 operation 标记 interrupted，进度查询返回中断终态，不自动重跑模型。

替代：全部重写为 SQLite 会扩大业务存储改动；只有内存 owner 会在重启后丢失隔离；把 ID 当秘密无法实现可靠权限校验。

### 4. 固定执行槽和统一持久化准入

为所有可能调用模型的操作提供共同的 admission/operation 边界。后台评估进入固定工作线程和有界队列；同步评估与反馈重评也使用同一调度器，保留现有成功响应结构，等待结果但受排队和执行期限约束。现有反馈服务在不明确是否需要模型时按高成本操作保守准入，不开放未计量的特殊入口。

准入事务检查邀请码有效、主体和全站日额度、容量，并为 operation 原子预留每日操作额度。日界采用 Asia/Shanghai；操作额度归准入日，模型尝试额度归实际尝试日。容量已满返回 `503 EXECUTION_CAPACITY_EXCEEDED`，额度或限流返回 `429`，包含 Retry-After；不创建额外任务线程。身份故障返回 503，禁止绕过准入。

排队取消且尚未执行材料或模型时可以一次性退回操作预留；一旦执行开始，成功和失败都计数。已开始模型尝试永不退回次数。预留、结算和释放使用 operation ID 幂等更新；日切不重新初始化未完成 operation。服务重启保守保留不确定已用额度，将未结束操作标为中断。

运行槽与结果缓存分离；缓存淘汰不能删除运行记录。达到总期限后设置停止标记，不启动新工具或模型调用；当前网络调用使用剩余期限和有界 HTTP 超时，真实执行结束前不释放槽。线程不能被安全强杀，不将“客户端超时”误作“后台已终止”。退出单个会话不取消主体工作，停用或到期邀请码则取消排队操作，并在每次外部模型调用前拦截运行操作。

### 5. 模型硬边界按尝试计数，不依赖 provider usage

给 DeepSeek 同步、异步及反馈调用统一传递 operation budget；每次实际 HTTP 尝试前在 SQLite 事务中占用一次主体操作/全站尝试名额，重试、协议回退均计数。新尝试前验证停止标记、期限、邀请码状态及剩余额度。

调用预算控制器是独立于现有研究轮数和工具次数的硬边界。未知 usage 仍消耗尝试额度；usage 仅作统计，不用于释放已发生尝试。对材料上下文、整个序列化请求（含提示和工具定义）限制大小，同时限制输出 token。预算耗尽转换成稳定的任务终态或 API 错误，不能由上层捕获后重新创建独立预算继续尝试。

初始建议值（均为可校验配置，非用户已确认的运营额度）：

| 配置 | 默认建议 |
|---|---|
| 邀请码有效期 / 会话绝对有效期 | 30 天 / 12 小时，会话不超过邀请码到期 |
| 登录尝试 | 每可信 IP 每 10 分钟 10 次；全站每分钟 60 次 |
| 一般业务请求 | 每邀请码每分钟 120 次；全站每分钟 600 次，覆盖进度轮询 |
| 执行并发 / 等待队列 | 2 / 4；每邀请码最多 1 个运行或排队操作 |
| 主体 / 全站每日高成本操作 | 5 / 30 次 |
| 每操作 / 全站每日模型尝试 | 40 / 500 次 |
| 排队 / 执行总期限 | 120 / 900 秒；单次 HTTP 不超过剩余期限 |
| 入站请求体 | 1 MiB，包括流式请求 |
| 模型请求 / 输出上限 | 序列化请求 1 MiB；输出最多 16,384 tokens，材料沿用现有限额 |
| 评估绝对保留 / 日志容量 | 24 小时；每日志文件 10 MiB，最多 5 个轮转备份 |

日额度和调用上限提供可计算的消耗边界，不等于货币精确上限；实际人民币预算需结合当前模型价格及提供商账户侧限制设置。初期不新增计费集成或 Turnstile，邀请码猜测和登录压力由高熵凭证、应用限流及 Cloudflare 边缘规则共同控制。

### 6. 公网请求和主机能力隔离

公网模式禁用环境授权接口及 readonly 输入，前端仅显示 manual/snapshot/later。图和 deterministic tool executor 中也必须关闭 collect-environment 能力；不能仅隐藏按钮或拒绝某一条 API。

请求体限制在 ASGI 接收层按实际字节累计，同时提前检查合法 Content-Length。允许 Host 和 Origin 使用明确配置的 `https://researchops-agent.com`；回环健康检查单独允许，不信任客户端提供的 Host 推导合法 Origin。跨站写请求缺少或错误 Origin 均拒绝；本地 CLI 不借用浏览器 API。

cloudflared 同机回环连接作为唯一生产代理，信任转发地址的前提是 TCP 对端匹配且公网没有其他源站入口。Uvicorn 的代理头处理明确配置，限流不要把已经改写的 remote address 当作原始代理证据；在改写前建立可信链，统一解析 CF-Connecting-IP/X-Forwarded-For。来自不可信 peer 的头全部忽略。该设计不防御已能在同机执行代码的攻击者，主机账号本身属于信任边界。

响应设置 nosniff、frame-ancestors 'none'、限制 Referrer-Policy、Permissions-Policy 和公网 HSTS；会话及业务数据 no-store，Cloudflare 配置禁用相应路径缓存。将内联脚本迁到静态文件或使用固定哈希，禁止 script-src unsafe-inline/unsafe-eval，样式按页面实际需要限制；外部内容统一 textContent/安全 DOM 构建，链接仅接受 http/https 并添加必要隔离属性。

### 7. 出站连接绑定校验结果

抽出共享出站策略和传输边界，覆盖项目页、GitHub、论文、HF、数据及 checkpoint 探测以及模型配置端点。固定提供商仍坚持已有域名白名单；通用项目页只允许公网 HTTP/HTTPS 的标准端口，拒绝 userinfo。

每跳解析完整 A/AAAA，任一非公网地址即拒绝；实际连接绑定已验证的地址，同时保留原始 hostname 的 Host、TLS SNI 和证书校验，连接池不得复用到未验证目标，重定向每跳重新校验。使用可测试的 HTTPX transport/网络后端，不采用“先检查 DNS 再交给普通客户端二次解析”的实现，也不以关闭 TLS 校验换取绑定 IP。所有采集保留现有大小与超时限制；模型服务不自动跟随重定向。

相比仅允许项目页域名白名单，绑定解析结果能保留现有任意公网项目页能力。传输实现必须有 DNS 变化、IPv6、重定向和 TLS hostname 回归测试；未达到这些条件前禁止公网启用通用抓取。

### 8. 显式 launchd 部署，先保护再接通

cloudflared 使用 `/etc/cloudflared/config.yml`，配置 tunnel 为已有 UUID；`ProgramArguments` 显式包含 `tunnel --config /etc/cloudflared/config.yml run <UUID>`。只安装该隧道 JSON 凭证；配置与凭证归属对应服务身份，目录 0700、文件 0600，不复制账户级 cert.pem。保留该域名 ingress 和末尾 http_status:404；日志等级 info，指标仅回环。

Python 从登录时 LaunchAgent 迁到系统 LaunchDaemon，明确 `UserName=lanting`、绝对 venv 路径、工作目录、`127.0.0.1:8000` 和一个 worker。system domain 不意味着应用以 root 运行；此阶段复用已有低于 root 的账号，不引入额外账号迁移。关闭旧用户 Agent 防止端口竞争，采用 `bootstrap/bootout/kickstart` 管理与状态检查。

隧道可保留系统级进程但仅访问最小凭证；Python 切勿 root 运行。防睡眠设置仅在交流供电下关闭系统睡眠，保留显示器睡眠；记录原值用于回滚。日志放受限持久目录，由应用轮转与 macOS newsyslog/等效有界方案覆盖隧道输出，避免无限增长和 /tmp 丢失。

FileVault 开启时，关机后可能必须人工解锁启动卷；服务在卷解锁后无需登录桌面即可启动的能力，须通过实际重启验收确认。不会默认关闭磁盘加密或开启自动登录。停电后的自动开机策略可由运维后续单独配置，不作为当前恢复隧道的隐含动作。

核对 Windows connector：Cloudflare 支持同隧道多个副本，但无防护旧副本必须停止或同等升级。当前无法验证 Windows 主机，验收必须留下该项外部证据。

## Risks / Trade-offs

### 质量门禁补充范围（2026-10-15 用户确认）

现有生产路径为 Context & Gap → Tool Acquisition → 局部 Evidence/Finding Draft → Rule。旧测试引用退役的整体 Research Planning、独立 Conflict/Finding 模型接口和全量 Evidence extraction。按现行阶段边界迁移测试夹具与断言，不恢复退役生产入口、不跳过业务断言。来源引用、材料隔离、结构化传输与回退、工具预算、错误分类、反馈重评和最终决定必须保留对应覆盖。遇到真实实现缺陷在原功能范围内修复。离线测试隔离目录和凭证；完整公网流程先注入可控模型和材料，再单独执行计入预算的真实模型验收。

相关修复作为实施前质量门禁，先于系统部署执行；不增加新的研究功能，不进行大规模架构重构。

- [邀请码被转发或泄露] → 每人独立发码、短期有效、额度共享、可撤销所有会话；系统无法区分同一码的真实持有者。
- [受邀用户可能提交敏感材料] → 严格归属、no-store、绝对保留期、日志最小化；模型调用仍会将必要材料发送给模型提供商，页面说明这一实际行为。
- [文件与控制库无法共同事务] → 先完成归属再公开，缺失归属默认拒绝，定期处理孤儿，备份同时覆盖两者。
- [同步调用不能强制杀死线程] → 有界网络超时、操作停止标记、槽延迟释放；异常阻塞时通过受控服务重启恢复，不虚报已取消。
- [单进程限制吞吐] → 符合当前主机与人数；扩为多进程前需要共享执行调度，不直接增加 worker 数。
- [应用限流无法独自抵御大量网络请求] → 配合 Cloudflare 边缘规则，真实付费动作始终受本地持久化硬上限保护。
- [FileVault 或 sudo 条件阻塞主机实施] → 交付模板及明确待执行步骤，不谎称已经完成系统部署或冷启动验收。
- [现有未提交业务改动较多] → 实施只改相关边界，保留现有用户改动，运行业务回归，部署前形成可回滚版本快照。

## Migration Plan

1. 记录当前 PID、监听端口、launchd 配置、电源设置、connector 状态，备份配置、评估文件和控制状态；不读取或写入日志明文秘密。
2. 在本地实现安全边界和管理 CLI，完成自动化验证；旧生产服务维持原状，不能先修隧道公开无防护版本。
3. 停止旧服务并备份最终数据；迁移数据库和保留期限封装，旧无归属数据保持不可公开，按需本地显式认领。生成至少两个测试邀请码验证隔离。
4. 安装非 root Python 系统服务，移除冲突的用户 Agent；先验证回环地址的登录、拒绝、额度和禁用探测。
5. 部署显式 cloudflared 配置和最小凭证，验证 ingress 与服务参数，确认 Windows 旧副本安全状态后启动；收集注册连接日志并验证公网登录入口。
6. 配置防睡眠、日志轮转、Cloudflare HTTPS 与敏感路径缓存策略。通过独立移动网络完成匿名、有效码、跨主体、撤销、限额和单次真实评估验收；真实模型验收计入预算，不为测试移除防护。
7. 验证异常退出、断网恢复和重启；重启前协调避免中断当前工作，记录 FileVault 解锁前提与登录前服务状态。不能验证的条件保留为待完成，不勾选验收任务。
8. 回滚：先停公网 connector/路由，再停止新服务、恢复旧配置及匹配的数据备份。旧无防护版本仅回环运行；重新公开必须重新验证安全边界。数据库破坏性降级前保留新库，不静默丢弃撤销或额度记录。
