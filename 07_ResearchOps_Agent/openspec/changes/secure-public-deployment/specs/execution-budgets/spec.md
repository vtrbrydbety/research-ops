# Spec Delta

## Purpose

为单台 Mac mini 上的 ResearchOps 建立可验证的资源和模型消耗边界。即使邀请码泄露、客户端并发请求或服务重启，也能通过统一准入和持久化额度控制任务数量，避免绕过限制消耗外部模型服务。

## ADDED Requirements

### Requirement: 登录与请求限流
系统 SHALL 对会话兑换按可信客户端地址及全局实施限流，对已登录业务请求按邀请码主体及全局实施限流。达到限制 MUST 返回 429 和 Retry-After，限制状态不得无限增长；调用方伪造转发头 MUST 无法绕过限制。

#### Scenario: 邀请码猜测触发限制
- **WHEN** 同一地址在配置窗口内持续提交邀请码超过上限
- **THEN** 后续兑换请求返回 429，且不签发会话

#### Scenario: 伪造来源和更换会话不绕过额度
- **WHEN** 调用方更换 Cookie 或伪造 X-Forwarded-For、CF-Connecting-IP
- **THEN** 系统只使用配置的可信代理来源，且同一邀请码仍共享业务请求额度

### Requirement: 所有高成本路径统一准入
新评估、后台评估及可能触发模型的反馈重评 MUST 共享全局并发上限、有界等待队列和主体额度。队列已满 SHALL 返回 503 和 Retry-After，额度不足 SHALL 返回 429；被拒绝请求不得创建工作线程或调用模型。

#### Scenario: 同步入口不能绕过后台限制
- **WHEN** 后台任务已占满执行槽和等待队列，用户改用同步评估或反馈重评接口
- **THEN** 同样返回容量不足，不增加运行任务数量、不调用模型

### Requirement: 原子持久化每日额度
系统 SHALL 按邀请码及全站维护每日高成本操作额度，按 Asia/Shanghai 日期结算，在准入时原子预留并持久化；重启、并发提交或跨日期排队不得重置或重复释放额度。模型或材料执行已经开始的失败任务 SHALL 计入额度。

#### Scenario: 并发争抢最后一个名额
- **WHEN** 多个请求同时争抢同一主体或全站剩余的最后一个每日名额
- **THEN** 最多一个请求成功预留，其余收到 429；重启后已预留或已消耗的额度仍然有效

### Requirement: 模型调用硬预算
系统 MUST 对每个高成本操作设置模型调用尝试次数、输入大小、单次输出 token 和总执行时限上限，并设置全站每日调用尝试上限。重试及协议回退 MUST 计入调用尝试；缺失 usage 不得使已发生尝试免计费，达到上限不得发起下一次模型请求。

#### Scenario: 重试与回退受同一预算约束
- **WHEN** 模型失败或工具协议回退需要额外尝试，但任务或全站尝试预算已用尽
- **THEN** 系统停止后续模型调用，返回可解释的预算耗尽结果，不通过重试或其他 API 绕过限制

### Requirement: 运行生命周期受控
任务超时、异常或停止时 MUST 最终释放执行槽；运行中任务不得因结果缓存淘汰而失去跟踪。重启后的未完成任务 SHALL 标记为中断且不自动重跑；已停用或到期主体的等待任务 MUST 不再启动，运行任务不得发起新的模型尝试。

#### Scenario: 超时不产生隐藏的运行任务
- **WHEN** 一个操作达到执行时限
- **THEN** 操作进入明确终态，停止后续模型尝试；底层仍在运行时不提前释放执行槽，确认终止后才允许下一任务占用该槽

#### Scenario: 撤销邀请码后等待任务停止
- **WHEN** 有等待和运行任务的邀请码被停用
- **THEN** 等待任务取消，运行任务在当前有界调用结束后停止后续尝试，不再访问外部模型
