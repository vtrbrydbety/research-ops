# Spec Delta

## Purpose

使每个受邀主体能够安全访问自己创建的任务和评估，并阻止不同邀请码之间读取或修改业务数据。归属规则覆盖后台生成与持久化恢复，避免将随机资源 ID 或登录状态误当成数据访问权限。

## ADDED Requirements

### Requirement: 服务端确定资源归属
系统 MUST 使用已验证会话中的邀请码主体为任务和评估记录归属，不得信任请求体提供的归属字段。后台任务及其最终评估、历史、反馈和最终决定 SHALL 保持同一归属。

#### Scenario: 后台评估继承归属
- **WHEN** 主体 A 启动后台评估且任务随后完成
- **THEN** 任务进度、评估结果及后续审阅操作均仅属于 A，客户端不能将其归属指定为 B

### Requirement: 所有资源操作检查归属
系统 MUST 在读取任务或评估、读取历史、提交反馈或最终决定之前检查主体归属；其他主体的资源与不存在的资源 SHALL 统一返回 404，且拒绝操作不得触发模型调用、修改数据或延长目标数据保留期。

#### Scenario: 跨邀请码读写被拒绝
- **WHEN** 主体 B 使用主体 A 的任务 ID 或评估 ID 请求进度、结果、历史、反馈或最终决定
- **THEN** 所有请求均返回 404，不返回资源内容、不启动重评且不改变 A 的数据

### Requirement: 归属在重新登录和重启后保持
资源归属 MUST 独立于单个浏览器会话持久保存；同一邀请码重新登录后 SHALL 能访问尚未过期的已有评估，服务重启不得使归属检查失效。后台任务不可恢复时 MUST 明确表示中断，不得自动再次调用模型。

#### Scenario: 服务重启后访问隔离不变
- **WHEN** A 的评估已持久化，服务重启后 A 和 B 分别重新登录
- **THEN** A 仍可访问有效评估，B 仍收到 404；未完成任务明确中断且不自动重跑

### Requirement: 历史无归属数据默认封闭
启用公网模式前产生的无归属评估 MUST 默认不向任何受邀主体开放。系统 SHALL 支持运维人员在本地按显式评估 ID 绑定归属并记录审计，不得将所有旧评估默认分配给首个登录者。

#### Scenario: 旧评估未迁移
- **WHEN** 已登录访客请求一个无归属的旧评估
- **THEN** 返回 404，旧数据保留在本地，不被自动认领或删除

### Requirement: 资源保留有界且不扩大
公网模式下评估及归属元数据 SHALL 具有可配置的绝对保留期限和容量上限；反复读取不得无限延长保留时间。清理 MUST 同步移除相关归属元数据，且不得因会话退出而删除仍在保留期内的评估。

#### Scenario: 持续读取不能永久保留评估
- **WHEN** 用户持续读取一份已达到绝对保留期限的评估
- **THEN** 系统返回 404 并按清理策略回收评估与归属记录，不因最近读取而延长绝对期限
