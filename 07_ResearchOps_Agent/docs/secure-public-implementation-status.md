## 实施与质量结果

OpenSpec 已完成 44/51 项。邀请码、安全会话、统一认证、数据归属、持久化额度、有界调度、模型预算、CSRF、请求与出站防护、页面入口和部署模板已实现。完整评估、反馈和最终决定已通过隔离集成验收。系统服务尚未切换，公网恢复尚未验收。

2026-10-15 经用户确认，将原有研究链测试契约修复纳入本次变更。测试现在使用 Context & Gap → Tool Acquisition → 局部 Evidence/Finding Draft → Rule，保留来源验证、故障分类、重试与预算、Unknown、冲突双方、去重、反馈与重启恢复等断言；没有恢复过时的整体分析入口。原有基线的 42 个失败、2 个收集错误和 10 个 Ruff 问题已消除。

本次还修复了真实功能缺陷：

- 局部分析线程显式复制可信主体及 operation 上下文，所有并行 HTTP 请求共享持久化模型预算。
- 后台进度的候选数量读取当前局部分析结果。
- 研究工具成功但没有新增材料时保留 `no_new_material`；环境采集失败提供 snapshot/manual 替代输入。
- 局部模型不能把确定性探测失败的 Finding 与对应 Evidence 分离；探测失败不等同于确认禁止访问。
- 页面增加最终投资决定记录入口，调用既有接口，与 Rule Gate 分开保存；在不同结果页均可使用。

浏览器检查仅替换材料 I/O 和模型 HTTP 响应，认证、Cookie/CSRF、调度、模型适配器、图、Rule 与持久化均执行实际代码，不使用生产邀请码或绕过预算。浏览器账本记录初评 10 次、反馈 2 次，最终决定不调用模型。

真实模型检查通过 `tools/check_live_model.py --run-live` 单独执行，限制最多 2 次 HTTP、每次输出最多 1,200 token、无常规重试、操作期限 90 秒。实际使用 1 次 HTTP；提供商报告总 token 5,042（含输入），操作结算为 completed。仅发送合成 README，临时账本结束后删除。此项验证模型连通性、结构契约和来源 Rule，不代替公网真实完整评估。普通 pytest 默认不读取付费密钥。

脱敏日志与验收 JSON 保存在本机 `.acceptance/secure-public-deployment/`，不纳入 Git。重新运行真实模型检查会产生新的调用及可能的费用，不能当作日常离线回归。
