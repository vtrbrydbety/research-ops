## 一、正式发放目标

- 面向最近 12 个月内真实尝试过开源 AI 论文或模型复现，或真实配置过深度学习项目环境的用户发放；
- 收集用户在复现结果、时间成本、阻塞阶段、可提前核验问题、当前解决方式、AI 操作授权边界和报告分享场景方面的数据；
- 保留不符合核心资格的结束路径数据，但不将其纳入核心问题统计。

## 二、数据来源标记

- `virtual_precheck`：虚拟用户预检数据，不进入正式统计；
- `real_pilot`：真实用户预测试数据，不进入正式统计；
- `regression_test`：V0.2 回归测试数据，不进入正式统计；
- `formal`：正式发放数据，完成清洗后可进入正式分析。

正式统计前必须确认测试答卷、预测试答卷与正式答卷能够区分。无法通过后台标签直接区分时，应使用提交时间、答卷编号及测试记录建立排除清单。

## 三、发放渠道与邀请说明

### 计划渠道

- AI 方向研究生群体；
- 科研实习生或研究助理；
- 算法工程师或研究工程师；
- 具有真实复现或环境配置经历的其他用户。

### 邀请说明要求

- 明确问卷预计完成时间为 5—8 分钟；
- 明确题目围绕最近一次真实经历作答；
- 明确没有相关经历也可以如实选择；
- 明确不收集 API Key、访问密钥或未公开材料；
- 如提交页出现第三方平台推广内容，说明其与本项目无关，本项目不承诺提供奖励。

|---|---|---|---:|---:|---:|---|---|
|  |  |  |  |  |  |  |  |

不得为了增加数量而使用虚拟 Persona、大模型模拟回答或无法确认存在真实经历的构造样本。

## 五、每日质量监测

正式发放期间每日检查：

- 新增答卷数量与提交时间；
- Q1 三条路径是否正常；
- 是否出现异常短时长、规律性选择、重复提交或明显乱填；
- Q11 互斥逻辑是否存在异常数据；
- Q17 四个文本字段是否能够正常保存；
- 是否出现跳转失败、无法提交或后台字段缺失；
- 是否收到新的理解、选项或移动端反馈。

发现异常时保留原始数据和证据，不直接覆盖用户答案。

## 六、暂停发放条件

出现以下任一情况时，暂停新增发放并登记 Issue Log：

- Q1 资格路径错误；
- 核心题无法显示或无法提交；
- 新增题目或题号在后台保存错误；
- 大量答卷出现相同逻辑异常；
- 手机端或电脑端出现影响完成的页面问题；
- 其他可能影响样本资格或核心研究结论的 P0/P1 问题。

问题修复后，应针对受影响路径重新执行回归测试，再决定是否恢复发放。

## 七、正式数据清洗要求

- 原始数据保持只读，清洗结果另存；
- 按 `20260804_Data_Cleaning_Rules_V0.2.md` 执行资格、重复、时长、互斥和质量检查；
- 正式清洗时验证 VP-003：当 Q7 为“完整跑通并达到接近目标的结果”且 Q8 为“尚未获得可用结果”时，确认 `consistency_flag=1`、`manual_review=1`；
- VP-003 命中后保留原始回答，进入人工复核，不直接删除整份答卷；
- 所有人工判断写入清洗日志。
