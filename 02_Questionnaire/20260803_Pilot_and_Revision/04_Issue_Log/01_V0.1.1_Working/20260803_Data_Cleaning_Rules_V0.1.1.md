# ResearchOps 数据清洗规则 V0.1.1

## 一、基本原则

1. 原始数据只读保存，不直接覆盖。
2. 清洗后的数据另存为新文件。
3. 所有删除、改码和异常处理都记录在清洗日志中。
4. 预测试阶段可以调整规则；正式问卷发放后不得根据结果临时修改规则。

---

## 二、样本处理规则

| 检查项 | 判定规则 | 处理方式 |
|---|---|---|
| 核心资格 | Q1 选择“复现过论文/模型”或“配置过项目环境” | 纳入核心样本候选 |
| 潜在用户 | Q1 选择“两者都没有” | 保留数据并标记为潜在用户，不纳入核心统计 |
| 答题时长异常 | 完成时间明显低于正常阅读与作答时间 | 先人工复核，不直接删除；具体阈值在预测试后确定 |
| 前后矛盾 | 例如 Q1 无相关经历，但 Q3 填写多次复现 | 人工核查；无法合理解释时标记为无效 |
| 重复提交 | 提交时间、设备、联系方式或回答内容高度重复 | 保留内容更完整的一份，其余标记为重复 |
| 关键字段缺失 | 核心样本的 Q1—Q3、Q7—Q10 或 Q14 大面积缺失 | 不纳入核心统计，但保留原始数据 |
| 明显乱填 | 连续机械选择、无意义字符、答案明显自相矛盾 | 人工复核后标记无效 |
| 开放题低质量 | Q16 仅填写“无”“不知道”“环境问题”等无法编码内容 | 仅标记开放回答无效，不删除整份问卷 |

---

## 三、Q7—Q8 结果一致性检查

### 触发条件

当一份答卷同时满足以下条件时，触发一致性复核：

- Q7 = “完整跑通，并达到接近目标的结果”
- Q8 = “尚未获得可用结果”

### 派生字段

```text
consistency_flag = 1
manual_review = 1
```

未触发时：

```text
consistency_flag = 0
manual_review = 0
```

### 处理规则

1. 保留 Q7 和 Q8 的原始回答，不覆盖或自动改写；
2. 不因该组合直接删除整份答卷；
3. 查看 Q9、Q10、Q16 等字段是否能够解释该组合；
4. 用户可能将“完整跑通”理解为程序流程已经执行完成，而将“可用结果”理解为达到目标指标或可继续用于实验的结果；
5. 若存在合理解释，人工复核后保留该答卷；
6. 若无法解释，并且同时存在极短完成时间、规律性选择、大量矛盾等其他低质量信号，再决定是否排除；
7. 在清洗日志中记录人工复核结论和判定依据。

### 清洗日志要求

命中该规则时至少记录：

- `response_id`
- `consistency_flag`
- `manual_review`
- 异常字段：Q7、Q8
- 原始回答
- 人工复核结论
- 是否纳入核心样本
- 处理日期
- 备注

除此之外，原有资格判断、完成时长、互斥选项和其他清洗规则保持不变。

---

## 四、多选题互斥规则

以下选项不得与其他选项同时出现：

- Q10：“未遇到以下问题”
- Q11：“没有使用以上方式”
- Q12：“没有明显不足”
- Q15：“不会使用或分享这类报告”

若发生冲突，先保留原始回答，再标记为“多选互斥冲突”，等待人工复核。

---

## 五、清洗日志字段

清洗日志至少记录：

- response_id
- 原始提交时间
- 原始完成时长
- 核心资格
- 异常类型
- consistency_flag
- manual_review
- 异常涉及字段
- 原始回答
- 人工复核结论
- 是否纳入核心样本
- 处理日期
- 处理人
- 备注
