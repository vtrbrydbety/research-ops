# ResearchOps Gate 1 Decision V1

## 1. Gate 结果

**Gate 1：CONDITIONAL PASS（有条件通过）**

当前证据支持“复现前准备度评估”继续作为首版 P0 主路径，
目标用户、核心场景和核心问题已能够形成一致的问题定义。

但准备度判断能否真实改变用户复现决策、判断准确性与可信度、
相对于现有替代方案的增量价值，以及 H4/H6 所涉及的真实行为，
仍需在下一阶段通过异步任务、竞品同题测试和 MVP 验证进一步确认。

因此允许进入 Sprint 2，但不得将尚未验证的能力提前扩大开发范围。

## 2. H1 / H4 / H6 阶段结论

### H1｜复现前条件判断具有高价值

**阶段结论：支持（Continue）**

问卷侧 19/20（95.0%）有效样本至少报告一项可在投入前核验的问题，
超过 H1 预设的 ≥60% 门槛；开放回答、公开失败案例及 FGI Founder Case
进一步提供了同方向的具体过程证据。

因此，继续将“复现前准备度评估”作为首版唯一 P0 主路径。

但当前证据主要来自用户自陈、公开失败案例及单一创始用户过程，
尚不能证明 ResearchOps 的准备度报告已经能够真实减少复现成本或改变用户决策。
下一阶段必须通过真实任务验证其实际决策价值。

### H4｜AI 建议与高风险执行分离，并保留人工审批权

**阶段结论：部分支持（Continue with Safety Constraints）**

问卷显示用户对不同风险等级操作的授权边界存在明显差异：
覆盖文件的非直接执行比例为 17/20（85.0%），删除文件为 18/20（90.0%），
均达到预设 ≥70% 的安全门槛；但安装依赖仅为 5/20（25.0%），未达到门槛。

因此，当前证据支持对高风险操作实施权限分级、解释和人工确认，
但不支持将所有安装、修改、覆盖和删除动作统一视为需要相同审批强度。

现阶段证据仍属于问卷态度，尚未观察用户在真实 AI 执行任务中的授权、
查看、拒绝或确认行为。H4 的完整验证继续留到后续异步安全任务。

### H6｜报告分享与轻量行动协同具有次级价值

**阶段结论：阶段性支持（仅限分享意愿层面，Defer Full Collaboration）**

18/20（90.0%）有效样本能够指出明确的外部分享对象，
超过 H6 预设的 ≥40% 门槛，说明准备度报告具有明确的潜在分享价值。

但当前证据只能证明“愿意分享”，尚未观察真实的报告分享、结论确认、行动项认领或状态更新行为；
同时存在 3/20 仅选择自留、1/20 表示不会使用或分享的反向证据。

因此，首版只保留只读分享、导出和轻量信息同步方向，不据此建设复杂团队协作、多人编辑或团队知识库。
完整 H6 需等待后续真实分享与行动状态任务验证。


## 3. P0 痛点与首版主路径

### 3.1 P0 痛点

Gate 1 后，首版 ResearchOps 聚焦以下四类相互关联的核心问题：

- P07：复现所需信息分散，缺少统一、可追溯的证据链；
- P01：数据获取、访问权限与路径要求难以及时确认；
- P02：依赖、版本与运行环境兼容信息难以提前判断；
- P03：预训练权重及关键运行配置的完整性难以确认。

上述痛点不作为四个彼此独立的产品功能，而统一收敛到“复现前准备度评估”这一 P0 主路径中。

### 3.2 首版 P0 主路径

首版唯一 P0 主路径为：

用户提供目标 AI 论文/开源项目
→ ResearchOps 聚合并核验关键复现证据
→ 对核心复现条件进行结构化准备度检查
→ 区分“已满足 / 阻塞 / 未知”
→ 给出可追溯证据与主要风险
→ 输出阶段性的“是否建议继续复现”判断
→ 给出优先级最高的前三步行动。

首版成功标准围绕“是否能够帮助用户更快形成可信的复现投入决策”建立，而不是以是否能够自动完成论文复现作为成功标准。

### 3.3 被降级或暂不进入首版核心范围的内容

1. P04 算力、显存与资源需求
   降级为 P1。
   首版仅提供能够从现有证据中识别出的基础资源风险提示，不承诺精确预测实际显存、运行时长或完整资源需求。

2. P05 运行后错误诊断
   降级为 P1 后续能力方向。
   不进入首版 P0 核心闭环，也不建设覆盖所有错误类型的通用 Debug Agent。

3. P06 评测口径与结果对齐
   暂列 P2 / 继续观察。
   当前不属于复现前最主要决策断点，不投入首版核心开发资源。

4. 复杂团队协作
   暂不进入 P0。
   首版最多保留只读分享、导出和轻量信息同步；多人实时编辑、复杂权限体系、团队工作空间和团队知识库暂缓。

5. 自动完整复现、模型训练与调参、GPU 调度、多 Agent / MCP 平台化、通用科研项目管理明确列入 Non-goals。



## 4. 反例、研究限制与剩余风险

### 4.1 反例与冲突证据

虽然当前证据总体支持“复现前准备度评估”继续作为 P0 主路径，但仍存在以下与主结论不完全一致的证据：

1. 并非所有用户都会明显遭遇可提前识别的复现阻塞。
   正式问卷中仍存在未报告相关问题的用户，说明部分经验较丰富用户、项目条件较完整的用户，可能已经具备自己的检查流程，ResearchOps 对这类用户的增量价值可能较低。

2. 并非所有复现失败都能够在正式运行前完全发现。
   公开案例中仍存在只能“部分提前发现”的问题，某些运行时错误、动态依赖问题和模型加载问题可能必须在实际执行后才能暴露。因此首版不能承诺“提前发现所有问题”。

3. H4 中不同风险操作的用户授权态度并不一致。
   用户对覆盖、删除等高风险操作表现出较强的人工确认需求，但对安装依赖等操作的接受度不同，因此不能采用统一的“一律自动”或“一律审批”权限策略。

4. H6 当前证明的主要是分享意愿，而不是真实协作行为。
   存在仅希望自留结果或不会使用分享能力的用户，因此不能据此推导复杂团队协作是首版刚需。

### 4.2 研究限制

1. 样本规模有限。
   当前正式有效问卷为 N_user=20，公开案例为 N_case_valid=20，结论适用于当前探索阶段的产品方向判断，不应外推为整体 AI 研究与工程人群的市场比例。

2. 存在便利抽样与样本结构偏差。
   当前用户样本无法完整代表不同资历、机构、研究方向及工业场景中的全部复现用户。

3. 问卷主要反映用户自陈态度和过往经验。
   H4 的权限边界、H6 的分享价值以及准备度报告是否真正改变决策，仍需要通过真实任务行为进一步验证。

4. 公开案例存在失败案例选择偏差。
   公开案例适合证明问题类型真实存在和补充问题模式，不能用于估计用户层面的实际发生率。

5. FGI Founder Case 为单一真实过程案例。
   其价值在于提供可追溯过程证据，不应作为频率或普遍性结论的依据。

### 4.3 Gate 1 后仍需承担的主要风险

- 决策价值风险：
  准备度报告可能能够发现问题，但未必足以改变用户的继续/暂停决策。

- 判断质量风险：
  “满足 / 阻塞 / 未知”的判断如果准确性不足，可能反而增加用户的核验成本或产生错误决策。

- 增量价值风险：
  尚未证明 ResearchOps 相比 README、GitHub Issue、搜索和通用大模型在同一任务下具有足够明显的效率与质量优势。

- 范围膨胀风险：
  运行后排错、协作、资源预测等需求真实存在，但若提前投入，可能稀释“复现前准备度评估”这一核心路径。

- 用户边界风险：
  当前尚未验证不同经验水平用户对准备度评估的价值感知是否存在显著差异。


  ## 5. 进入 Sprint 2 的硬约束

Gate 1 判定为 CONDITIONAL PASS，因此允许进入 Sprint 2，
但下一阶段必须遵守以下约束：

1. P0 主路径不得扩张
   Sprint 2 继续围绕“复现前准备度评估”展开，不得因为新增想法将运行后排错、复杂协作、资源调度或自动复现提前提升为 P0。

2. 必须验证真实决策价值
   下一阶段需要通过真实任务验证：用户看到准备度报告后，是否会实际选择继续、暂停或调整复现计划，不能仅以“用户觉得有帮助”作为核心成功标准。

3. 必须验证判断准确性与可解释性
   对“已满足 / 阻塞 / 未知”的准备度判断，需要验证其准确性、证据可追溯性以及用户是否能够理解和信任。

4. 必须完成竞品同题测试
   ResearchOps 需要与 README、GitHub Issue、搜索和通用大模型在同一复现判断任务下进行比较，验证其在完整性、可追溯性、判断效率和行动建议质量上的增量价值。

5. H4 / H6 不得提前宣称完整验证
   H4 仍需通过真实安全操作验证授权、确认和拒绝行为；
   H6 仍需通过真实报告分享与行动状态任务验证实际协作价值。

6. P1 能力不得影响 P0 成功标准
   运行后辅助诊断、复杂资源预测和团队协作均保持 P1 / 后续方向，不作为首版是否成功的主要判断依据。

7. 新证据若推翻当前定义，必须留下变更记录
   若后续证据要求修改目标用户、P0问题或产品边界，必须记录“原结论 → 新证据 → 调整内容 → 影响范围”，不允许静默扩展功能范围。


## 6. Gate 1 最终结论

基于 20 份正式有效问卷、20 条独立公开案例、开放文本证据及 FGI Founder Case 的多源证据，Gate 1 判定为 **CONDITIONAL PASS（有条件通过）**。

当前证据支持“用户在正式投入 AI 论文/开源项目复现前，缺少统一、可追溯的准备度判断过程”作为首版 P0 问题，因此下一阶段继续以“复现前准备度评估”为唯一 P0 主路径。
但准备度判断的真实决策价值、准确性与可信度、相对于现有替代方案的增量价值，以及 H4/H6 对应的真实行为，仍需在 Sprint 2 中继续验证。
在上述条件获得进一步证据之前，不得将自动完整复现、通用 Debug Agent、复杂团队协作、GPU 调度或平台化能力扩展为首版核心范围。
